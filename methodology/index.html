Bureau of Model Containment · Field Manual

Methodology

The icons on each card open the story that broke the case and the model's rap sheet. Learn more about how to interpret the app as well as my methodology in assigning scores in the Threat Matrix in my announcement post.

How the filters work

The sliders button in the corner of the registry opens four filters. They narrow the Case Timeline, the Threat Matrix, and the Cases by Lab chart all at once.

When you set more than one filter, a case has to match all of them to stay on the page. While a filter is narrowing the list, a red dot sits on the button and a line under the tabs says how many files are showing. A Clear filters button appears once any filter is set and resets all four.

Class

Class sorts cases by how far the model got into somebody else's systems. It's the colored badge on each card and the color down the card's left edge.

Class I · No intrusion
The model got out but never got inside anyone else's systems. It tried and failed, or it acted only through public pages and forms, such as filing a tip with a government agency.
Class II · Intrusion
The model got into a real organization's systems using techniques that were already well known.
Class III · Severe
The model got into a real organization's systems through a security flaw nobody had patched yet. This is the most serious tier in the registry.

Lab

Lab narrows the registry to the companies that built the models involved, including models the lab never named. It's the only filter that takes more than one choice. Check two labs and you'll see the cases from either one.

The list of labs is built from the cases themselves, so a new lab shows up here as soon as its first case is added.

Outcome

Outcome records whether the model got what it went after.

Succeeded
The model got what it went after, whether that was getting into somebody's systems, getting a form through, or getting out of its sandbox.
Failed
The model tried and didn't get it. Outcome judges the break-in rather than the escape, so a model that got out of its sandbox but couldn't get into its target counts as failed.

Kind

Kind describes what the model reached for once it was loose.

Break-ins
The model went after somebody else's systems, whether or not it got in.
Unauthorized actions
The model used a public page or form to do something nobody asked it to do, such as filing a tip, submitting a form, or editing a public wiki.
Escapes only
The model got out of its sandbox but didn't go after anyone else's systems or act through a public page.

How Class, Outcome, and Kind differ

The three filters answer different questions about the same case. Kind says what the model went after, Outcome says whether it got it, and Class says how far into somebody else's systems it ended up. A failed break-in, for example, is a break-in by kind and failed by outcome. It lands in Class I because it got inside nobody's systems.
